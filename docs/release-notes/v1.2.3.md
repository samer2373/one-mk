# oneMK 1.2.3: lighter and quieter

oneMK now asks less of your computer, especially while its window is open and while a wallpaper is showing. Nothing you use changed.

## What is new

- **The window polls the service far less.** In front of you it still updates at once. When it is behind other windows it checks every 2 seconds instead of twice a second, and when it is minimised or covered, every 10 seconds. After you change something it refreshes immediately. In a test with the window unfocused, the window's wake-ups fell from 8.3 to 3.6 a second and the service's from 2.1 to 0.5.
- **Less memory in the window.** Fonts for other scripts (Chinese, Korean, Arabic and so on) are kept once instead of twice, and are looked up once per script instead of once per letter, so a page of names no longer freezes the window. The 3D desk stops redrawing text at a new size on every frame, and the wallpaper picture and the keyboard model are let go when you leave those pages.
- **The service reads its settings files only when they change** (82 file opens became 4 over 40 status requests), no longer stops to ask GNOME about the wallpaper while it is forwarding your mouse and keyboard, and starts about 18 fewer idle threads on GNOME (22 became 3 or 4; 1.48 GB of reserved address space became 335 MB).
- **Pictures as wallpaper use much less memory on GNOME.** An 8K picture used 190 MB while showing and now uses 15 MB, with an identical picture. Videos use less memory and CPU (a 4K video went from 308 MB to 169 MB), and a picture is no longer stopped and drawn again every time you lock the screen.
- **Smoother wallpaper video across computers.** Small differences between computers' clocks no longer make the video skip forward every half minute.
- **Smaller things.** The keyboard layout is read once instead of every time the pointer crosses. On X11, mouse movements oneMK makes itself are no longer echoed back to it. The clipboard watcher and the discovery thread only run when they are needed. On Windows and Mac, the file-drop listener only runs while dropping files is switched on, and the keyboard and mouse path skips per-device matching when you have no per-device rules. A diagnostic log setting (`RUST_LOG`) is read by a lighter parser, and a stub program that was never used is no longer shipped.

The Windows and Mac changes were built and tested, but not yet run on real Windows and Mac computers. If the pointer, your keys or file dropping feel any different, please tell us.

Nothing about pairing, sharing, the update key or the update format changed.
