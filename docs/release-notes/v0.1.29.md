# oneMK 0.1.29: safer updates, honest labels and a polish pass

This release is mostly about trust: what oneMK checks before it installs something, what it tells you about itself, and which features are proven on real computers and which are not. Nothing here changes how pairing or sharing works day to day.

## Security

- **Package updates on Debian and Ubuntu are checked again with the password step.** The one step that runs as administrator used to trust a checksum and a version handed to it by the program that started it, so another program running as you could have staged its own package and asked for the same password prompt. That step now verifies the signed release list itself, against the key built into oneMK, refuses anything not newer than what is installed or older than a list it accepted before, copies the package into a private file while checking its size and checksum, and installs exactly that copy. The password dialog has its own message and asks every time.
- **`install.sh` verifies what it downloads.** It checks the file against `SHA256SUMS` and, where OpenSSL 3 is available (most Linux systems), the signed release list and the file's checksum in it. On a Mac it also checks the app's code signature. Without OpenSSL 3 it says the signature was not checked. It refuses archives with paths outside their folder, and replaces programs by renaming complete copies, so re-running it while oneMK is running no longer fails halfway with "Text file busy".
- **Passwords you copied are not sent by accident.** `one-mk clip-send` refuses a copy that a password manager marked sensitive unless you add `--allow-sensitive`; when you do, the mark travels with it, so the other computer never records it in its history or passes it on.
- **A custom `--home` no longer rewrites your real "Send to" entries.** Pairing and forgetting in a throwaway settings folder used to point your own file manager menus at it.
- **A security policy** ([SECURITY.md](../../SECURITY.md)) with a private way to report problems, and a plain statement of what the update signature protects and what it does not.
- **Licences.** Every package now carries the licence texts and a list of the third-party software and fonts inside it. The crates declare their licence (MIT or Apache-2.0).
- **A bad release can be withdrawn.** The release tooling can now mark versions as revoked or raise the minimum version that may update in place.

## Reliability

- **No lost layout changes.** A `one-mk layout` that the running service had just confirmed could be silently undone, and a forgotten computer could come back. Changes to your paired computers are now serialised and written safely.
- **A computer that forgot this one says so.** After `one-mk forget` on one side, the other showed it as "offline" for ever and redialled every few seconds. It now says "removed this computer" with what to do, tries only every 10 minutes, and `one-mk doctor` stops blaming the network.
- **One bad line in `settings.toml` no longer disables everything.** Only its own section or rule is skipped, and the line is named in `status`, `doctor` and `keymap check`. Commands that change settings still refuse a file they cannot read in full, so a hand edit is never overwritten.
- **The emergency chord works after crossing with a held key.** With `edge --modifier shift`, `Ctrl+Alt+Shift+Esc` did nothing until you pressed Shift again.
- **Ctrl+C on `one-mk send` tells the other computer.** It closes the link with "the sender cancelled" and says "what arrived is kept, send again to resume", instead of leaving the receiver to time out.
- **A test or second settings folder can no longer start or stop your real login service.** On a Mac the LaunchAgent is only loaded or unloaded from your own home folder, and on Linux the systemd service only when the unit is where systemd reads it. Before, opening the window on a throwaway `--home` could replace the installed oneMK.
- **Settings folders are created private** even when your umask would make them group-writable.
- **A controlled computer is no longer let go after one minute.** Reading a page or watching a video on the other computer used to lose the pointer. The idle release is now **10 minutes** by default and yours to set on the controlled computer: `one-mk edge --idle-return 30m` (10 seconds to 24 hours, or `off`).
- Clearer messages: a `join` that is refused says who refused it; a settings folder path too long for the control socket is a clear error instead of an endless pairing retry; "saved, but the running oneMK did not confirm it" when the service hangs; `switch next` with no other computer says so; two computers with the same name ask for the id.

## Honest labels

- **Typing the letters printed on your keys (Letters and Auto) is labelled experimental** in the window, the help and the command output, with what each paired computer will really do. It only works toward Windows and Mac computers and has not run on real hardware.
- **Rules for your own keyboard (local key rules) are experimental and appear only on Windows and macOS,** where they were already included in builds. They are off by default.
- **File edge drops are off by default everywhere, experimental on X11, Windows and macOS, and not available on Wayland** (the command refuses and the window hides the switch there). `one-mk send` and the file manager's "Send to" are the supported ways.
- **Wallpaper** says what is experimental on your computer: macOS, Windows, Wayland desktops other than GNOME, video on GNOME, sharing across computers, and the smaller copy of large videos.
- Per-device rules say they are inactive where the desktop cannot tell keyboards apart; the fullscreen guard and per-app rules say when Wayland or macOS cannot show the focused window; the pointer "acceleration" option, which never worked, is hidden and refuses with an explanation (turn acceleration off in your system's settings).
- The README now has a platform table with three honest levels: verified on real hardware (Linux with GNOME on Wayland), experimental, and not available.

## Window

- The Desk's second view is named **Arrange** everywhere, the last "Advanced" and "Layout" wording is gone, and Health shows its `Ctrl+5` shortcut.
- The window is calmer when idle: the connection graph redraws a steady line rarely and a new one at once, and the status polling slows down while the window is minimised or unfocused. On a computer with software graphics, idle CPU on Desk fell from about 7% to under 1%.
- The tray's **Remove** asks first, and its start-at-login switch follows `--home`.
- The Updates card says a failed check once. The Wallpaper page keeps its labels at the smallest window size.
- Health and `one-mk doctor` report a layout the pointer cannot cross, and leave out checks that do not apply to you (`doctor --all` shows them).
- **If oneMK cannot start, the window says why at once** (for example "UDP port 24900 is busy") with a **Show log** action, instead of waiting four seconds and saying it "didn't answer".
- **Dragging a monitor on the Desk lands where the screens touch.** A casual drag could save a placement where they did not, and the pointer then could not cross.
- **Keys:** a drag that starts on a key turns the keyboard at once, and the turn eases into a readable angle. A hover tip no longer stays stuck on screen.
- **Computers with the same name** (two "MacBook-Pro") show as `name (id)` wherever they could be confused, every hint is a command that works, and `one-mk rename <computer> <new name>` gives a computer a name of your own here.

## Wallpaper

- Picture wallpapers put back **exactly your own GNOME wallpaper** when you turn them off, including settings that were at the desktop default. The saved original survives a crash or a power cut.
- Pictures on desktops that do not read GNOME's wallpaper settings (KDE, Xfce, Cinnamon...) are refused with a clear message instead of a fake success.
- `one-mk uninstall` turns the wallpaper off, puts your own back (even with no service running) and removes oneMK's GNOME extension.
- The GNOME extension accepts every GNOME Shell 50.x release (a point release used to break video silently), detects an older copy and updates it on Install, and other GNOME versions get a plain "not supported" message.
- A shared video that is shown as a still because the extension is not active says so, with the one step that fixes it.

## Clipboard & files

- An empty copy is called empty, not "switched off". `history persist on` prints the plain-text warning, and turning persistence or history off waits until the saved file is gone.
- Files: a failed save shows the whole reason, names of 255 bytes stay valid when numbered, a verified file that cannot be placed is removed instead of left hidden, and unfinished files older than 7 days are cleaned up (`one-mk partials` shows and clears them).
- `one-mk send` follows a symbolic link named on the command line, sends a path named twice once, and reports skipped links, pipes and empty folders in one line. A dropped-file notice is a real notification and respects `notify off`.
- The window's clipboard size limit matches the command line's (up to 256 MB).

## Input

- Dead controls are refused instead of saved: the left and right mouse buttons cannot be mapped to nothing, the emergency chord cannot be remapped, and a gesture on autoscroll's toggle button is refused when added. `keymap check` flags the same mistakes in hand-written files.
- `autoscroll --reset` removes an override; messages say what happened; rules that would be ignored because the settings folder is group-writable are called out when added.
- `edge --side X --reset` makes that edge follow the shared rules again (the window's "Use shared rules"); its help said it turned every rule off.
- `one-mk hotkeys --off` says the emergency chord still works.

## Docs & packaging

- **A new README** with a screenshot, a short pitch, the platform table, a quick start for each system and one paragraph per feature. The long reference material moved into `docs/`: a generated [command reference](../COMMANDS.md), [arranging](../ARRANGING.md), [input](../INPUT.md), [clipboard](../CLIPBOARD.md), [files](../FILES.md), [automation](../AUTOMATION.md), [window and tray](../WINDOW.md), [troubleshooting](../TROUBLESHOOTING.md), [security model](../SECURITY-MODEL.md), and a guide to [testing on real hardware](../TESTING.md). The Windows page now says plainly what works and what does not exist.
- Fresh screenshots of the current window.
- The release is gated on the test suites and clippy on Linux, macOS and Windows, a licence check and the installer checks; a tag release fails loudly if the macOS signing secrets are missing.
- Contributing guide and issue forms. About 40 MB of internal working files were removed from the repository.

## Still not verified on real hardware

Windows, macOS, KDE Plasma, wlroots compositors and the X11 backend on a real desktop have never been run by the maintainer; everything marked experimental above and in the docs is in that state. If you have one of those, [the testing guide](../TESTING.md) is the most useful thing you can do for the project.
