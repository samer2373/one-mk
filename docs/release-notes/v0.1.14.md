# one·mk 0.1.14 — wave 5

These notes describe the next release. The maintainer assigns the release version;
the wave-5 development tree still reports 0.1.13 until that separate step.

## New ways to share

- Broadcast your mouse, keyboard and scrolling to connected computers together.
  Stop using the keyboard shortcut, not a click in the window: captured clicks
  go to the other computers. **Stop service** stops sharing entirely.
- Pair without network discovery using an expiring, one-use invitation and
  `one-mk join LINK`. The invitation is a secret; share it privately.
- Opt into clipboard history, reveal a masked entry, restore it, or clear it.
  The window has a history switch. History is off by default, including upgrades;
  saving history to disk is a separate opt-in and stores unencrypted text.
- Fetch a peer's clipboard when that source explicitly allows it. Fetch permission
  is off by default. File drag/drop and clipboard file transfer remain available.
- See a live network round-trip graph, arrange multi-monitor layouts and offsets,
  use pointer wrap and accept a learned layout suggestion.
- Configure forwarded per-device input rules, autoscroll and mouse gestures.
  The keys/mouse editor shows these settings in the window.
- Signed-release checking and portable-install updates are implemented, but remain
  disabled until the publisher configures the release signing key. Package-managed
  installations use their package manager. No silent update installation.

## Upgrade notes

- New default shortcuts are **Ctrl+Alt+B** for broadcast and **Ctrl+Alt+V** for
  clipboard fetch (Windows uses Ctrl+Alt+Shift+B/V). They are announced once on
  upgrade. Change or disable them with `one-mk hotkeys --help` if they conflict
  with an application. The fetch chord is registered only when fetching is
  permitted locally or by a connected modern peer.
- Settings use `settings_version = 2`. Versioned fetch opt-ins are retained;
  old unversioned `allow_pull` settings are treated conservatively and require
  explicit re-enabling. Review the clipboard privacy notice after upgrading.
- Existing pairing identities and layouts are retained. Back up your settings
  folder before upgrading or downgrading; do not delete your identity files.
- Restart older daemons after replacing the programs so the window and daemon
  use the same feature set. An older daemon cannot apply the new history switch.

## Experimental or not included

- Wallpaper policy, consent, diagnostics and the optional GNOME component are
  experimental and off by default. **There is no live wallpaper playback.**
  Enabling wallpaper policy does not launch a renderer. The developer-only Linux
  media importer is not included in release packages and needs an audited sandbox
  runtime; its output is not a playable scene.
- Native local key remapping requires a separate build feature and is not in
  release builds. Preferences can be saved but do not enable that missing feature.
- Character/letter typing is not included. Physical-key forwarding is supported;
  match the keyboard layouts on both computers. Character/auto preferences remain
  visible as unavailable rather than promising working letter injection.
- The privileged Windows service for login/UAC screens is not shipped.

## Known limitations

Windows and macOS have compile checks, not native end-to-end acceptance testing.
Portal permissions, real hardware, secure desktops and platform clipboard behavior
still need native testing. X11 app-based clipboard skipping cannot identify
Wayland-native applications, and unmarked secrets cannot reliably be detected.
Idle CPU was measured near zero without peers; each connected peer still causes
about 4–5 timer wakeups per second for keep-alive. Window graph repaint cost needs
release-build measurements on a real GPU.
