# oneMK 0.1.22: steadier crossing, and a hidden pointer on GNOME

## New

- **Hide the pointer on GNOME (Wayland), with a small optional extension.**
  GNOME draws this computer's pointer where it left, while the mouse is on
  another computer. With the extension it is hidden then, and when another
  computer has moved this one's pointer and lets go, it stays hidden until you
  use this computer's own mouse or trackpad. Install it with
  `one-mk pointer-extension install`, log out and back in once, then
  `one-mk pointer-extension enable`. Nothing changes without it, and the
  pointer can never stay hidden: it comes back if oneMK stops, and if nothing
  renews the request for 15 seconds. See `docs/POINTER-HIDE.md`.

## Fixed

- **GNOME: crossing stopped working after a layout change.** Moving a
  computer in the Arrange view (or any monitor change) while sharing was on
  made GNOME refuse the new edges ("Session already enabled"); the old ones
  stayed, no longer matching the layout, so the pointer was handed back or
  came in at the wrong place. The edges are now replaced properly, and
  changes made during a visit wait until the pointer is home.
- **The pointer no longer bounces back from the computer it was sent to.**
  While one computer controls another, the edge the pointer enters and leaves
  by was still armed on the controlled one, so GNOME captured the pointer it
  was being sent and the controlled computer started crossing back by itself:
  jumps, a small pause when coming back, and entering at a different point.
  A controlled computer now arms no edge, and refuses any crossing it did not
  start.
- **The window no longer jumps while you cross.** The banner about control
  moving between computers made the screens above fit their space again at
  every crossing. It now stays for a few seconds, so the desk holds still.
- **Mac: the pointer comes back without a brief freeze.** After returning
  from another computer macOS sometimes ignored the mouse for about a quarter
  of a second. The pointer is now put back with the display call that
  doesn't do that (in tests it never froze; the old call froze about one
  return in five).

- **GNOME: copy and paste between computers stopped working after a while.**
  GNOME starts and stops its X11 compatibility layer (XWayland) as it likes,
  with a new credentials file each time. oneMK kept the first one, so after a
  restart it could neither read this computer's clipboard nor set the other
  computer's text here ("Authorization required" in the log), until oneMK was
  restarted. It now follows to the current file, opens the clipboard again if
  the connection died, and the clipboard history watcher reconnects.

## Better to diagnose

- The log says why a link to another computer closed: a timeout (the network
  dropped out, or that computer slept) is a warning.
- The log says how long the other computer took to accept the pointer, with a
  warning above 120 ms, and how long each visit lasted.
